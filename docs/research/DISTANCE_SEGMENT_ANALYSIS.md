# Distance segment analysis — partial Corner Intelligence

Status: **implemented, interactive, exploratory; not validated corner intelligence**. Base revision `5cdac66677e6abb513f84e3ede5f74dd74d00bb6`. This adds an analysis to the existing replay telemetry comparison without another clock or new source feed.

`apps/web/src/lib/telemetry-segments.ts` divides the existing shared distance grid into up to 12 nearly equal index windows, with adjacent windows sharing their endpoint. For each window and each lap it reports sampled entry/minimum/exit speed, the first grid point after raw brake crosses from zero to positive, throttle crosses from below 50 to at least 50 provider percent, and any reported gear change. Crossings require known values on both sides; missing values are counted and not imputed. These thresholds are exploratory conventions, not certified physical braking onset or throttle reapplication. There is no smoothing, de-noising, or corner classification. Source throttle is not clipped. Windows are based on speed-integrated estimated distance and are **not surveyed named corners**. Equal estimated distance does not guarantee identical physical position for the two laps.

Segment time is `delta_B_minus_A(end) - delta_B_minus_A(start)`, in seconds. Window deltas telescope to the shared-grid terminal delta; the terminal grid point can precede the end of the shorter integrated lap and cannot generally be equated to full-lap time difference. `TelemetryPanel.tsx` highlights the selected grid interval and seeks the existing canonical clock using reference lap A's start UTC and elapsed A time. The normal circuit map and other panels respond through their existing clock; no distance-to-geometry or invented corner mapping is asserted. Pit, tyre, fuel, weather, traffic and source timing confounding remain uncontrolled. Laps can belong to different race times.

## Actual local example

The existing OpenF1 Monza 2025 #1 lap 50 versus #4 lap 50 comparison, `data/processed/telemetry_comparisons/monza-2025_driver_1_lap_50_vs_4_lap_50.json`, SHA-256 `9bc3aa5ea7750541deff8d10a4f84f8f228e0c5e372f85692e1923821d8dfea6`, contains 1,150 grid samples. Window 4 covers estimated 1,435–1,915 m and the B−A delta changes by +0.1279825 s. Its shared-grid terminal B−A is −0.2339377 s while the saved full-lap duration difference is −0.1740 s; this discrepancy illustrates the differing endpoints, not a claim of speed or driver skill. Existing local sources and artifacts remain unchanged. Source access/redistribution remains subject to the OpenF1 and underlying data terms; no telemetry source is bundled by this change.

## Verification and reproduction

Run `npm --prefix apps/web run lint`, `npm --prefix apps/web run test:unit`, and `npm --prefix apps/web run build`. The unit tests use synthetic samples to verify telescoping deltas, missing channels and transition boundaries. With the existing three local replay packs and Monza telemetry artifacts available, run `PYTHONPATH=src npm --prefix apps/web run test:e2e -- e2e/replay.spec.ts --grep 'distance segment selection|telemetry crosshair follows'`; this checks real source samples, synchronized clock behavior and desktop/mobile interaction. Captured renderings: [desktop](../images/distance-segments-desktop.png), [mobile](../images/distance-segments-mobile.png). The local audit used an alternate Playwright output directory and a temporary Vite allow-list because its worktree reused installed dependencies by symlink; these audit-only configuration files are not required in a normal checkout.

Further work: surveyed or explicitly estimated circuit-linked geometry, rigorously validated braking events and corner segmentation, comparable boundary alignment, similarity retrieval, channel-quality handling, more sessions/drivers, accessibility review, and measured end-to-end performance.
